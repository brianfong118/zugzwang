# Design

Decisions and their reasons. When a decision changes, mark the old one superseded rather than deleting it.

## Toolchain
- C++20, CMake, Ninja. GCC/Clang via MSYS2 UCRT64 on Windows; GCC on Linux CI. One compiler family means one flag set shared by dev machine and CI: `-march=native` on top of CMake's `-O3` in Release; `-fsanitize=address,undefined` in Debug on Linux (MinGW GCC lacks ASan, so CI runs the sanitizers).
- `<bit>` over intrinsics: portable, identical codegen at `-O3`.
- Flags live on one `zugzwang_options` INTERFACE target that every executable links, so the engine and the tests are always built the same way.
- Engine sources compile once into a static library `zugzwang_core`; `main.cpp` holds only the entry point. The test binary links the same objects the engine ships, and supplies its own `main` so it can run `attacks::init()` before Catch2 starts.
- MinGW builds link `-static`. The engine binary is copied next to lichess-bot and must not depend on whichever MSYS2 runtime DLLs are on PATH; a toolchain newer than the installed `libstdc++-6.dll` otherwise fails at load with `STATUS_ENTRYPOINT_NOT_FOUND`.
- Catch2 via FetchContent. Perft is the primary correctness check; unit tests cover FEN round-trips, UCI parsing and eval symmetry (mirrored position, negated score).
- CI builds Release and Debug on every push and runs the tests under sanitizers, excluding `[slow]` perft cases. Debug adds `-fno-sanitize-recover=all`, because UBSan otherwise only prints a message and exits 0, and CI could never fail on undefined behaviour.
- CI's build job times out after 20 minutes. A broken time or stop limit makes a test hang rather than fail, and GitHub's default timeout is six hours.
- CI pins `clang-format` to 21.1.8. Versions lay out the same code differently, so an unpinned runner fails code that is correctly formatted locally. Update the pin when the local version changes.

## Board
- Bitboards: one per piece type per colour, two colour occupancies, plus a 64-entry mailbox so piece-at-square is a lookup, not a 12-bitboard scan.
- Magic bitboards for sliders, magics found at startup. Avoids committing a table; measured cost is ~200 ms per process with an untuned seed (rooks need ~1M candidate multipliers, bishops ~80k). Per-rank tuned seeds would cut that to ~10 ms if startup time ever matters; it does not for lichess-bot or SPRT. PEXT can be added behind an `#ifdef` later.
- Leaper tables (pawn, knight, king) are `constexpr`: zero startup cost and testable with `STATIC_REQUIRE`. Slider tables cannot be, since the random magic search exceeds compile-time evaluation limits.
- `attacks::init()` is explicit, called from `main()` and the test main, rather than a static initialiser. Nothing that runs during static initialisation can then depend on the tables being ready.
- Slider lookups stay inline in the header (`Magic` table declared `extern`) because they sit on the move-generation hot path; the search that fills the tables lives in the `.cpp`.
- One fixed-seed SplitMix64 PRNG (`prng.h`) serves magic search and Zobrist keys: the same magics and hashes every run, so bench and hash-dependent behaviour are reproducible.
- `kCastlingRules` is the one description of castling geometry. Move generation, FEN validation, rights loss and the rook's move all read it, so they cannot disagree.
- Make/unmake with an undo stack rather than copy-make: cheaper once state grows to include NNUE accumulators.
- The undo stack is a `std::vector` in `Position`, reserved to 1024 entries. Any game length fits with no overflow handling, `Position` stays small, and `make` allocates only if a game outgrows the reservation. Each entry keeps the position's key, which repetition detection will walk. A copy does not inherit the reservation, so `search` calls `reserveHistory(kMaxPly)` before it starts. `make` then never allocates mid-search, even on the copy the search thread works on.
- Zobrist hash updated incrementally from day 1: needed for repetition detection in v1 and the TT in v1.1.
- 16-bit moves (from, to, 4 flag bits for promotion/castling/en passant). Compact in move lists and TT entries. No capture or double-push flag: the mailbox gives the captured piece and the distance moved gives the double push.
- Pseudo-legal generation, legality checked in make. Simpler than legal generation; the wasted work is small. `make` returns false and restores the position itself on an illegal move, so no caller can forget the cleanup. The castling attack rules live there too, so legality has one home.
- `generateMoves` produces every move. `generateNoisy`, added for quiescence in v1.0, produces the moves that change material: captures, en passant and queen promotions. Stockfish's capture generator likewise includes queen promotions. Underpromotions are left out. One beats a queen only by giving a knight check or avoiding stalemate, and quiescence sees neither checks nor stalemate. Both lists come from one template, so they cannot disagree on what counts as a capture. The full list keeps its order, so the bench is unchanged.
- `MoveList` is a fixed array, so generation never allocates, and `Move`'s trivial default constructor means declaring a list writes nothing. Capacity is 415, a proven bound, rather than the conventional 256. 218 is the known maximum for legal positions, but `fromFen` also accepts positions no game can reach, and a search found a 28-piece FEN with 267 pseudo-legal moves. `fromFen` therefore caps each side at 16 pieces, and the bound follows: 15 queens of 27 moves, plus a king's 8 and 2 castles.
- `Position::fromFen` returns `std::optional` rather than throwing: the UCI loop must survive a bad `position` command, and the codebase has no exceptions. Validation is structural: at most six fields, so a mistyped `moves` keyword cannot be silently dropped; eight ranks of eight; exactly one king per side; at most sixteen pieces per side; no pawns on the back ranks; an en passant square on the correct rank, empty, with the pushed pawn in front of it and that pawn's origin empty; and clocks of at most 1,000,000, so `make` cannot overflow them. One check goes beyond structure and supersedes the earlier "structural only" rule: the side not to move must not be in check, which also rejects adjacent kings. Otherwise pseudo-legal generation would offer a king capture, and `kingSquare` is undefined with no king on the board. `fromFen` therefore needs `attacks::init()` to have run. It is also the only way to create a `Position`, so every `Position` has two kings. A castling right whose king or rook is not on its home square is dropped rather than rejected (as Stockfish does), so the board guarantees the invariant "right set ⇒ king and rook at home" and castling generation need not re-check it.
- The en passant square is stored and printed as given, but hashed only when a pawn of the side to move attacks it. FIDE repetition compares the set of legal moves, so an uncapturable ep square must not distinguish two otherwise identical positions. Pins are ignored: a pinned pawn still counts, which can only miss a repetition in that rare case, and a full legality check is not worth running on every double push.
- Zobrist keys are a `constexpr` table generated from the fixed-seed PRNG; the sixteen castling keys are indexed by the rights mask so an update is `key ^= castling[old] ^ castling[new]`. Piece placement updates the key incrementally from the first `putPiece`; `computeKey()` recomputes from scratch and exists only to check the incremental key in tests. `unmake` restores the key from the undo entry rather than reversing the XORs. `putPiece` and `removePiece` still hash during `unmake`, and the result is overwritten. Avoiding that gains 2-4% in perft but needs a second pair of helpers, which is not worth it before search exists to profile.

## Search
- v0.2: iterative deepening and negamax alpha-beta on a material-only eval. This supersedes the original plan to start search in v1. v0.2 already needed `go`, `stop` and `bench`, so it needed a search, and a placeholder that played random moves would have been thrown away.
- v1: quiescence (captures only, stand-pat), MVV-LVA ordering. Quiescence is in v1 because material-only eval without it hangs pieces at the horizon and the bot would look broken rather than weak.
- v1.x: transposition table, killer and history ordering, null-move pruning, late move reductions, check extensions, aspiration windows. One change per SPRT.
- Search runs on a worker thread; the UCI thread only parses input and requests a stop. Required for `stop` to work mid-search.
- The worker is a `std::jthread`, and stops are sent through its `std::stop_token`, the standard cancellation channel, rather than a hand-rolled atomic flag. A `jthread` stops and joins in its destructor, so no exit path can leave the search running. A default-constructed token never stops, so tests and `bench` call `search` with no thread at all.
- The node limit is checked at every node, so `go nodes` is exact. The clock and the stop request are read every 1024 nodes. Reading the stop token at every node cost about 12% of bench nps; every 1024 nodes it costs nothing measurable, and a stop still lands within about 50 µs.
- An interrupted iteration is discarded, and the result is the last completed one. Depth 1 always completes, so there is always a move to play. A root with no legal move stops after depth 1, since deeper searches cannot change the result.
- `Position::isDraw(ply)` covers the fifty-move rule and repetition, where `ply` is the distance from the search root. If the earlier occurrence is after the root, a second occurrence is already a draw: whichever side steered into the cycle can repeat it again. If the earlier occurrence is the root or before it, the game rule applies and a third occurrence is needed. Ethereal draws the line in the same place, and Stockfish's `StateInfo::repetition` encodes the same split. The scan covers only plies within the halfmove clock, since a capture or pawn move cannot be undone. Within that range it checks only even distances of four or more, because a repeat needs the same side to move and undoing a move takes at least four plies.
- The fifty-move rule ignores the exception for checkmate on the hundredth ply, as Ethereal does. Honouring it needs a legal-move search at every such node, and the case almost never arises.
- Negamax: every score is from the side to move, so one function serves both colours and a child's score is negated on return.
- Fail-soft alpha-beta: a node returns its best score even when that falls outside the window. It costs nothing over fail-hard, and the tighter bounds pay off once the TT and aspiration windows store and reuse them.
- Mate is scored `kMate - ply` for the side delivering it, so the search prefers the fastest mate and, when losing, the slowest. `kMaxPly` (128) bounds the depth, the PV and mate distances.
- The PV is collected bottom-up. Each node passes its children a line, and on a new best move copies the child's line behind that move. No global table is needed, and the line is always the one that produced the score.
- Iterative deepening runs from depth 1 even before anything can interrupt a search. `stop` and time limits will take the move from the last completed iteration, and each shallower iteration costs a small fraction of the next one.

## Evaluation
- v0.2: material only, with the Chess Programming Wiki's Simplified Evaluation Function values (100, 320, 330, 500, 900), scored for the side to move. It exists so the search has something to maximise; PeSTO replaces it in v1.
- v1: tapered material + PeSTO piece-square tables. Public, known-good values; removes tuning from the critical path to Lichess.
- v2: NNUE. HalfKA-style features, one hidden layer, int16 accumulators updated incrementally in make/unmake, SIMD inference. Training data from self-play of the best v1.x build so the net is trained on this engine's own data, not Stockfish's. Trainer in `trainer/` (Python, PyTorch). Nets attached to GitHub Releases, not committed.

## Time management
- v1: budget `remaining/30 + increment` per move, hard cap `remaining/10`. Stop iterating when the next depth is predicted not to fit.
- v0.2: `timeBudget` returns `min(remaining/30 + increment, remaining/10)`, and the search treats it as a hard limit, since nothing predicts iteration cost yet. remaining/30 assumes about thirty moves are left. The cap matters on a low clock with a large increment, where remaining/30 + increment would spend a quarter or more of what is left. `movestogo` is ignored: for any value up to 30, remaining/30 is at least as cautious as dividing evenly.
- Only the side to move's clock is read; the other is validated and ignored. Given both a clock and `movetime`, the shorter limit wins, as in Stockfish. There is no move-overhead allowance yet. The cap leaves a margin, and lag handling belongs to the v1 work, measured against Lichess.

## UCI and Lichess
- `uci`, `isready`, `ucinewgame`, `position`, `go` (`wtime btime winc binc movetime depth nodes infinite`), `stop`, `quit`. Extensions: `bench`, `perft <depth>` (divide output).
- Command-line arguments are joined and run as a single command, after which the engine exits, as Stockfish does. Testing tools such as OpenBench call `engine bench` this way, and `zugzwang perft 5` works too.
- Every output line is flushed. lichess-bot reads through a pipe, which buffers by block, so an unflushed `uciok` would never arrive. Every write also takes one mutex, because the search thread prints `info` and `bestmove` while the UCI thread answers `isready`.
- `go` values must be positive integers, except clocks and increments, which may be zero (`winc 0` is how lichess-bot reports no increment). `depth` is capped at `kMaxPly`, and parameters the engine does not use are ignored. A `go` with no limit is treated as `go infinite`. `go infinite` holds `bestmove` until `stop` even if the search ends first, as UCI requires; the worker waits on a `condition_variable_any` with the stop token. With no legal move the answer is `bestmove 0000`, the UCI null move.
- `info` lines carry depth, score, nodes, nps, time and the PV. Mate scores are given in moves, negative when the side to move is being mated, as UCI specifies.
- `go`, `perft`, `bench` and `quit` stop a running search first. `position` during a search changes only the UCI thread's position, since the search works on its own copy. `ucinewgame` has nothing to reset until the TT exists, so it is ignored like any unknown command.
- At end of input, a limited search runs to completion and an infinite one is stopped. Stockfish treats end of input as `quit`. Letting a limited search finish keeps `echo "go depth 6" | zugzwang` and the in-process tests deterministic, and an infinite search could never end otherwise.
- The command loop takes streams rather than `std::cin` and `std::cout`, so tests drive it in-process. It starts in v0.1 with `position`, `perft` and `quit`, because debugging perft needs `position` to reach the failing line.
- `position` builds a separate `Position` and swaps it in only if the FEN and every move are valid, so a bad command leaves the current position untouched. Move text is matched against `generateMoves` output, since `make` trusts its input.
- `perft` makes every move, including the last ply. Bulk counting the final ply needs a legal move list, and generation here is pseudo-legal. Its depth is capped at 64, because it recurses once per ply and an unbounded depth overflows the stack.
- The official lichess-bot Python bridge connects the binary to Lichess. A hand-written bridge signals nothing; the official one already handles the Bot API, challenges and clocks.

## Measuring strength
- `bench`: fixed positions at fixed depth, prints total nodes and nps. The node count is a fingerprint — it changes iff search or eval behaviour changed.
- The bench set is ten positions: the start position and the five other perft suite positions for tactics, castling and promotions, two common openings, a Lucena rook endgame and Fine #70, a pawn endgame. The endgames add few nodes today, but they will exercise the TT and endgame eval once those exist. Depth 5 takes about half a second in Release, so it can run on every change. The depth goes up as the search gets cheaper per ply, and each raise is a logged bench change.
- CI runs `bench` in both builds and checks the output format. Release and Debug give the same node count, so the search does not depend on optimisation level, and the Debug run puts the whole search under the sanitizers.
- SPRT with fastchess at 8+0.08 against the previous accepted build. Lichess rating is the public scoreboard, not the development signal.
- SPRT starts in v1.0, which supersedes the plan to start it in v1.1. Quiescence, MVV-LVA, PeSTO and time management each aim to change playing strength. Bench only shows that the search changed, not that it plays better, and a feature that looks right but loses games fails its SPRT.
- The book is `noob_3moves.epd` from the official Stockfish books repository: 150,932 balanced positions three moves in, saved as `tools/book.epd` (gitignored). UHO books start from deliberately unbalanced positions to cut the draw rate between strong engines. This engine rarely draws, so a balanced book is simpler until its draw rate climbs. Every book position parses in `fromFen`, which was checked, so no game can start from a rejected position.
- Each opening is played twice with colours swapped, so an opening's bias cancels within the pair. fastchess plays two games per round by default; `-repeat` states it explicitly.
- Bounds are [0, 5] normalized Elo with alpha = beta = 0.05: H0 is no gain, H1 a gain of 5. Normalized Elo is fastchess's default model, and the command names it so the units are explicit. Large early gains pass within a few hundred games.
- The baseline is the last accepted build, kept in `baseline/` (gitignored). After a passing change is committed, its build replaces the baseline. Each run's games go to `sprt/last.pgn` for inspecting losses. fastchess also autosaves its state as `config.json` in the working directory so a run can resume, so `-config outname` moves that file into the ignored `sprt/` too.
- fastchess is v1.8.2-alpha, built from source and installed to `~/.local/bin`. Every fastchess release carries the alpha suffix.
- The setup was checked with 200 games of v0.2 against itself, using the `/sprt` command capped at 100 rounds. All games ended by mate or a draw rule, with no time losses, illegal moves or crashes, so the time budget holds at 8+0.08. The result was +8.7 ± 31.8 Elo, consistent with zero, which is the expected outcome for identical engines.

## Repository policy
- Public from day 1, MIT.
- Claude Code writes the code; the user reviews and commits. `.claude/settings.json` denies `git commit` and `git push` so the boundary is enforced, not just requested.
- Gitignored: build output, `lichess-bot/` (holds the API token), training data, nets, opening books, `.claude/settings.local.json`.
